# UnHelper

UnHelper는 Coupang Shipments와 WMS의 반복 업무를 보조하는 Windows 데스크톱 앱입니다. `RAW > Milkrun`과 `RAW > 트럭` 다운로드, Excel RAW 시트 반영, 일별 입고 상품 상세와 SKU 무게 분류를 자동화합니다.

## 입차순번

메인 `입차순번` 탭은 설정에서 연결한 Excel의 `입차순번` 시트를 읽어 외부대기, 출차, 각층 목표치의 차량 대수와 층별 팔렛트 상세를 보여줍니다. 탭에 처음 들어갈 때 한 번 자동 갱신하며 이후에는 `새로고침` 버튼으로 Excel의 최신 값을 다시 가져옵니다. Excel이 열려 있으면 여러 Excel 인스턴스 중 정확한 파일 경로의 통합문서를 찾아 저장 전 현재 화면 값을 읽고 파일을 닫거나 저장 상태를 변경하지 않습니다. 닫혀 있으면 매번 새 읽기 전용 인스턴스로 열어 값을 읽은 뒤 Worksheet·Workbook·Excel 참조를 모두 해제하고 종료하므로 SharePoint/OneDrive 동기화 파일도 연속 새로고침할 수 있습니다.

`AB:AC` 18행 이후의 `MBN…`은 RAW Milkrun의 `M…`, `tbn00…`은 RAW 트럭의 `T…` 예약번호와 연결합니다. 일치하는 금일 차량은 RAW 표의 팔렛트 수와 경량·중량·고단·양곡·미분류를 사용하므로 `AP/AW`에 함께 존재하는 금일 값은 사용하지 않습니다. RAW에 없는 전일 차량만 `AP` 또는 `AW`의 팔렛트 수를 사용하며 둘 다 같은 값이면 한 번만 계산합니다. 두 값이 다르면 임의로 합산하지 않고 상세 표에 확인 필요로 표시합니다. `AT`가 비어 있으면 외부대기, `1F` 또는 `2F`가 있으면 해당 층 출차로 표시합니다.

각층 목표치는 `AO8/AP8`의 1F T/M, `AO10/AP10`의 2F T/M과 `AO11/AP11`의 T/M 차량 대수 합계를 표시합니다. 외부대기와 출차의 T/M/이관 값도 모두 차량 대수입니다. 외부대기·출차·각층 목표치 카드는 작업 현황을 한눈에 비교할 수 있도록 한 줄로 나란히 표시합니다. 차량 대수 표 아래에는 층별 상세를 `구분 | 팔렛트 수` 2열 표로 정렬해 1F와 전일자의 총 팔렛트를 각각 한 행으로 표시하고, 2F에는 총 팔렛트와 경량·중량·고단 포함·양곡 포함·미분류 수량을 여섯 행으로 표시합니다. 상품 메모리에 영구 저장된 고단·양곡은 RAW 표의 일시적인 자동 경량·중량 표시보다 우선합니다. 한 트럭 또는 한 Milkrun 배차의 여러 SKU 중 고단이 하나라도 있으면 해당 차량의 전체 팔렛트를 고단으로, 고단 없이 양곡이 하나라도 있으면 전체를 양곡으로 집계하며 두 분류가 함께 있으면 고단을 우선합니다. Milkrun 상세에서 여러 SKU 행이 공유하는 팔렛트 수는 `배차번호 + 내부 Milkrun 번호`별로 한 번만 더합니다. RAW 표에서 분류를 수동 변경하거나 설정의 상품 분류 메모리를 수정하면 연결된 Excel을 다시 읽지 않고 현재 RAW 표 기준으로 2F 상세 수량을 즉시 재계산합니다. 각층 목표치는 전일자 상세 없이 1F와 2F만 표시합니다. 차량 대수 표와 층별 상세 표는 노트북의 낮은 화면에서도 글자가 잘리지 않도록 행의 최소 높이를 보장하며, 화면이 좁거나 낮으면 입차순번 화면의 가로·세로 스크롤로 모든 카드를 확인할 수 있습니다. 이관 차량은 RAW 상품 정보가 없어 차량 대수에만 표시되고 팔렛트 상세에서는 제외됩니다. `RAW 미매칭` 도움말은 입차순번 또는 층 배치에는 있지만 현재 선택 기준일의 앱 RAW 표에 같은 T/M 예약번호가 없어 팔렛트 상세에서 제외된 차량을 뜻합니다. RAW 표가 모두 비어 있으면 금일과 전일을 안전하게 구분할 수 없으므로 Excel을 읽기 전에 RAW 데이터를 먼저 얻거나 저장 표를 가져오라는 안내를 표시합니다.

각층 목표 배치 상세는 `Raw_트럭!B2:C…`와 `Raw_밀크런!B2:C…`의 층·번호를 사용합니다. Excel C열의 번호에는 `T/M` 접두사가 없으며 원본을 변경하지 않습니다. 앱이 비교할 때만 트럭 번호에는 `T`, Milkrun 번호에는 `M`을 붙여 RAW 표와 연결하고, 1F·2F별 차량 대수, 목표 대수, 총 팔렛트와 경량·중량·고단·양곡·미분류 팔렛트를 계산합니다.

메인 화면의 `기준일`은 기본적으로 `자동 (실행일)`이며 작업을 실행한 날짜를 사용합니다. `수동`을 선택하면 지정한 날짜를 기준일로 사용합니다. Milkrun은 기준일 전날부터 기준일까지 조회한 뒤 기준일 전날 행을 제외하고, 트럭은 기준일 하루만 조회합니다. 변경한 기준일은 즉시 저장되어 다음 실행에서도 유지됩니다.

완성된 RAW Milkrun·트럭 표는 기준일별로 로컬에 자동 저장되며 최근에 만든 2개 기준일만 유지됩니다. 앱을 실수로 종료해도 같은 기준일을 선택하면 WMS에 다시 접속하지 않고 표와 저장된 SKU 무게·분류를 복원합니다. 같은 기준일의 복원된 표나 가져온 표가 있는 상태에서 `데이터 얻기`를 누르면 `이어서 진행`, `처음부터 다시`, `나중에`를 먼저 선택합니다. 이어서는 현재 표를 유지하고 저장 무게가 없는 SKU만 확인하며, 처음부터 다시를 선택한 경우에만 Shipments 조회·다운로드·상세 수집 구간을 처음부터 실행합니다. 이때도 저장된 WMS 무게는 재사용합니다. 다만 상세 미확인 원본 합계 행이 하나라도 있으면 WMS 이어하기로 고착되지 않도록 Shipments 상세 조회부터 자동으로 다시 시도합니다. 메인 화면 하단의 `표 내보내기`는 선택한 기준일의 두 RAW 표와 그 표에 포함된 SKU 메모리만 JSON으로 저장하고, `표 가져오기`는 다른 사용자가 만든 파일을 불러옵니다. 중복 SKU는 현재 값과 가져올 값이 실제로 다를 때만 팝업을 띄우며 `덮어쓰기` 또는 `기존 유지`를 SKU마다 선택합니다. WMS 계정, Excel 경로와 다운로드 경로는 공유 파일에 포함되지 않습니다. v1.0.11 이하에서 저장된 트럭 표에는 컨테이너 Barcode가 없으므로 공유 컨테이너가 있는 날짜는 업데이트 후 `데이터 얻기 > 처음부터 다시`를 한 번 실행해야 차량 총 팔렛트 중복 제거 정보가 새로 저장됩니다.

각 RAW 탭 하단의 `연결된 Excel RAW 시트에 반영` 체크박스는 기본적으로 켜져 있으며 Milkrun·트럭 탭이 같은 설정을 공유합니다. 체크를 끄면 다운로드 파일의 검증·예약번호 추출, 일별 입고 상세 조회, WMS 무게 확인과 앱 표 저장은 그대로 진행하지만 연결된 Excel의 `Raw_밀크런`·`Raw_트럭` 시트는 열거나 지우거나 저장하지 않습니다. 선택 상태는 다음 실행에도 유지됩니다.

## RAW > Milkrun

`데이터 얻기`를 누르면 다음 순서로 동작합니다.

1. Coupang Shipments를 열고 사용자의 로그인이 끝날 때까지 제한 없이 대기합니다.
2. `입고 스케줄 > 밀크런 입고예약 목록`으로 이동합니다.
3. 조회 기간을 기준일 전날부터 기준일까지로 지정하고 `안산2` 센터를 선택합니다.
4. 조회 후 텍스트 다운로드를 요청하며, 사유는 `MM.DD-MM.DD` 형식으로 입력합니다.
5. 요청 완료 팝업을 닫고 텍스트 다운로드 내역으로 이동합니다.
6. 유형, 사유, 요청시각, 준비 상태가 모두 일치하는 가장 최신 행의 파일을 내려받습니다.
7. 다운로드 파일 첫 번째 시트의 C열 `입고일`을 확인해 기준일 전날 행을 제외합니다.
8. Excel RAW 반영을 선택한 경우 설정에서 연결한 Excel의 `Raw_밀크런!C1:P1000` 값을 지운 뒤, 남은 기준일 데이터를 `C1`부터 값으로만 붙여넣고 저장합니다.
9. 같은 로그인 세션으로 `일별 입고 현황`에서 안산2와 기준일을 조회합니다.
10. 기준일 전날 입고 행을 제외한 다운로드 첫 시트의 A열 배차번호를 `M` 접두사로 변환해 Milkrun 카드와 연결하고 상품 목록을 표시합니다.
11. 저장되지 않은 SKU를 WMS `재고관리 > 상품관리`에서 조회해 상품 무게를 가져옵니다.
12. WMS 상품관리의 무게는 1유닛 기준이므로 `상품 무게(g) × (발주확정수량(유닛 수) ÷ 팔렛트 수) ÷ 1000`으로 1팔렛트 중량을 계산합니다. Milkrun 상세의 그룹 `박스 수`는 계산에 사용하지 않으며, 280kg 이상은 중량, 미만은 경량으로 표시합니다.

## RAW > 트럭

트럭 탭도 한 번의 `데이터 얻기`로 전체 파이프라인을 처리합니다.

1. `입고 스케줄 > 트럭 입고예약 목록`으로 이동해 조회 시작일과 종료일을 모두 기준일로 지정하고 `안산2`를 선택합니다.
2. 텍스트 다운로드 사유에 `MM.DD`를 입력하고, 다운로드 내역에서 유형이 `트럭 입고예약 목록`인 최신 파일만 내려받습니다.
3. 파일의 A열 `예약번호`, E열 `거래처 이름`, M열 `유닛 수`, N열 `팔렛트 수`를 예약별로 연결합니다.
4. Excel RAW 반영을 선택한 경우 연결된 Excel의 `Raw_트럭!C1:U1000` 값만 지운 뒤 다운로드 값을 `C1`부터 값으로 붙여넣고 저장합니다.
5. A열 예약번호에 `T` 접두사를 붙이고 카드 전체 표시 텍스트에서 명시적인 `T…` 번호를 찾아 일별 입고 현황의 실제 카드만 정확히 일치시킵니다. `<b>` 같은 강조 태그나 상태 문구의 표시 순서에는 의존하지 않으며, 상세의 `truckContainerList`에서 PALLET 컨테이너별 SKU 정보를 수집합니다.
6. 수집이 모두 끝난 뒤 저장되지 않은 SKU만 WMS에서 조회합니다. 저장된 SKU 무게는 WMS에 다시 접속하지 않고 사용합니다.
7. 컨테이너 수량을 SKU별 팔렛트 수, 총 수량을 SKU별 유닛 수로 사용합니다. 같은 SKU가 여러 PALLET 행에 있으면 두 값을 각각 합산하되, 동일한 컨테이너 Barcode가 HTML rowspan으로 여러 SKU 행에 반복되면 차량 총 팔렛트에서는 한 번만 계산합니다.
8. `유닛 수 ÷ 팔렛트 수`로 팔렛트당 유닛을 구하고, `단위 무게(g) × 팔렛트당 유닛 ÷ 1000`으로 1팔렛트 무게를 계산합니다. 280kg 이상은 중량, 미만은 경량이며 수동 고단·양곡은 계속 유지됩니다.

같은 예약번호가 여러 행에 나오면 M/N 값이 동일할 때만 하나의 예약으로 사용합니다. E열 거래처 이름은 같은 예약의 모든 SKU에 적용하며, 거래처명이 서로 충돌하거나 M/N 값이 충돌하거나 한쪽만 입력된 경우에는 `Raw_트럭`을 지우기 전에 오류로 중단합니다.

## 다중 SKU 입고 그룹

하나의 Milkrun 번호 또는 트럭 예약에 서로 다른 SKU가 여러 개 있으면 모든 SKU 행을 유지한 채 같은 차량의 행이 연속되도록 정렬합니다. 거래처 이름과 동일한 배차번호·예약번호 셀을 병합하고 그룹마다 은은한 배경색을 교차 적용해 한 차량이라는 점을 직관적으로 표시합니다. 같은 거래처명이나 같은 내부 Milkrun 번호가 반복되더라도 바깥 `M…` 배차번호가 다르면 별도 차량으로 유지합니다. Milkrun RAW 표에는 `M` 접두사가 붙은 배차번호를 표시·저장합니다. 트럭은 컨테이너 정보에서 SKU별 팔렛트·유닛 수를 얻으므로 각 SKU의 팔렛트 무게와 분류를 자동 계산합니다. 반면 다중 SKU Milkrun의 팔렛트 수는 여러 SKU가 공유하므로 SKU별 유닛 무게만 조회·저장하고 팔렛트당 유닛과 1팔렛트 무게는 `?`로 표시합니다. 각 SKU 행의 분류 버튼으로 경량·중량·고단·양곡을 개별 지정할 수 있으며 수동 분류는 상품 메모리에 저장됩니다. 단일 SKU Milkrun은 기존처럼 자동 계산합니다.

로그인과 추가 인증은 Chrome 창에서 직접 진행해야 합니다. 로그인 대기는 시간 제한이 없으며, 앱의 `작업 중지` 버튼이나 Chrome 창 닫기로 끝낼 수 있습니다. 입고 스케줄, Milkrun·트럭 목록과 일별 입고 현황 메뉴는 표시된 한글·영어 문구가 아니라 고정된 앱 경로로 찾아 Shipments 메뉴 언어가 달라도 같은 흐름으로 이동합니다.

일별 입고 상세 상품 조회와 WMS 무게 측정 중에는 메인 화면 하단에 완료 건수, 완료율과 남은 비율이 표시됩니다. WMS 측정이 중단되거나 일부 SKU가 실패하면 체크포인트가 유지됩니다. `이어서 진행`은 현재 RAW 표와 이미 저장된 성공 SKU를 사용해 미완료 WMS 조회만 계속합니다. `처음부터 다시`는 Shipments 조회·파일 다운로드·Excel 반영·상세 상품 수집을 처음부터 실행하지만, 트럭과 Milkrun 모두 이미 저장된 WMS 상품 무게는 재사용하고 실제로 무게가 없는 SKU만 상품관리에서 조회합니다. 기존 고단·양곡 수동 분류도 그대로 유지됩니다.

다운로드 기본 경로는 `%USERPROFILE%\Downloads\UnHelper`이며 설정에서 변경할 수 있습니다. 각 실행은 전용 임시 다운로드 폴더를 사용하고, 완성된 지원 형식만 최종 폴더로 이동합니다. 자동화 실패 시 같은 폴더에 화면 PNG와 HTML 진단 파일을 남깁니다.

RAW 작업 전 설정에서 파일명에 `입고스케줄관리`가 포함된 `.xlsx`, `.xlsm`, `.xlsb`, `.xls` 파일을 연결해야 합니다. Excel RAW 반영을 사용할 때 대상에는 `Raw_밀크런`과 `Raw_트럭` 시트가 있어야 하며 읽기 전용이면 안 됩니다. 이 기능은 Windows용 Microsoft Excel 데스크톱 앱이 설치된 PC에서 동작합니다. 다운로드 원본은 Excel 형식과 CSV/TSV/TXT를 지원하며, 대상 범위를 넘는 데이터는 기존 값을 지우기 전에 중단합니다. 값 전용 대입을 사용하므로 대상 시트의 기존 서식은 유지됩니다.

설정의 WMS ID/Password는 저장되지 않은 SKU의 무게를 자동 조회할 때 사용합니다. Password는 Windows DPAPI로 현재 Windows 사용자만 복호화할 수 있게 보호합니다. 이미 저장된 SKU 무게는 WMS에서 다시 조회하지 않고 현재 행의 박스/팔렛트 비율로 경량·중량을 다시 계산합니다. 표의 분류 버튼 하나를 눌러 경량·중량·고단·양곡을 순환 변경할 수 있습니다. 수동 경량·중량은 현재 표시에서 적용되고 다음 데이터 조회 때 자동 계산으로 돌아가며, 수동 고단·양곡은 이후 조회에서도 계속 유지됩니다.

저장 상품 목록은 설정에서 경량·중량·고단·양곡별로 확인할 수 있습니다. JSON 가져오기/내보내기에는 SKU ID, 상품명, 무게, 수동 분류와 측정·계산 정보가 포함되며 WMS 계정은 포함되지 않으므로 다른 사용자가 분류한 상품 메모리를 그대로 가져와 사용할 수 있습니다. 가져오기에서 중복 SKU의 상품명·무게·분류·계산값이 모두 같으면 묻지 않고 기존 값을 유지하며 실제 값이 다를 때만 덮어쓰기 여부를 묻습니다. 상품명은 실제 줄바꿈만 공백으로 바꾸고 `/`를 포함한 나머지 문자열을 그대로 저장하며 표에서도 자동 줄바꿈하지 않습니다. 저장 파일은 `%LOCALAPPDATA%\Mrbinggrae\UnHelper`에 유지됩니다. 일부 레코드가 손상돼 전체 검증에 실패해도 입차순번 집계는 안전하게 확인된 SKU별 수동 분류를 읽기 전용으로 복구하고 경고를 남깁니다. 설정에서 전체 복구를 선택하면 원본을 백업하고 빈 목록으로 초기화할 수 있습니다.

RAW Milkrun·트럭 표 제목 옆 검색창에서는 거래처 이름, 배차번호·예약번호, SKU ID, SKU 명을 함께 검색할 수 있습니다. 여러 SKU가 한 차량으로 병합된 경우 한 SKU만 검색되어도 차량 그룹 전체를 표시합니다. Milkrun과 트럭 카드 매칭은 카드 전체 표시 텍스트의 명시적인 `M…`/`T…` 번호만 사용하므로 강조 태그, 강제예약·예약완료·발송 확정 상태, 여러 발주서 번호의 순서에 영향을 받지 않습니다. 트럭 카드 또는 상세 상품을 확인하지 못한 예약은 다운로드 원본의 거래처·예약번호·유닛·팔렛트 합계를 미분류 행으로 남기고, SKU 무게와 분류는 확인 가능한 상세만 처리합니다. Milkrun 상세 페이지에 상품 데이터가 없는 예약은 해당 번호만 건너뛴 뒤 나머지 예약을 계속 조회하며 완료 로그와 경고에 번호를 표시합니다.

작업 오류 팝업에서는 상세 traceback과 최근 로그를 확인할 수 있습니다. GitHub 신고 버튼은 민감정보를 가린 보고서를 UnHelper 이슈로 자동 등록하고, 같은 오류가 있으면 기존 이슈에 댓글로 추가합니다. 설정의 `업데이트 내역` 버튼에서는 설치된 버전의 변경 기록을 확인할 수 있습니다.

메인 화면 하단의 `로그 접기/펼치기` 버튼으로 진행 로그 영역만 숨기거나 다시 표시할 수 있으며, 선택 상태는 다음 실행에도 유지됩니다.

## 개발 실행

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe App.py
```

ChromeDriver는 `C:\Users\mrbin\Python\deadline\마감\chromedriver.exe`를 공용 원본으로 사용하고, 빌드할 때 UnHelper에 복사해 번들링합니다. 설치된 앱은 개발 PC의 절대 경로에 의존하지 않습니다.

## 테스트

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
$env:QT_QPA_PLATFORM='offscreen'
.\.venv\Scripts\python.exe App.py --smoke-test
```

실제 Shipments와 WMS 로그인 이후 구간은 사내 인증이 필요하므로 사용자가 릴리즈 환경에서 확인해야 합니다.

## 릴리즈 빌드

```powershell
.\.venv\Scripts\python.exe build_release.py un
.\.venv\Scripts\python.exe build_release.py un --installer
```

`release` 폴더에 다음 자산을 만듭니다.

- `UnHelper_manifest.json`
- `UnHelper_patch.zip`: 모든 버전에서 쓸 수 있는 전체 패치
- `UnHelper_delta_patch.zip`: 직전 버전과 파일이 달라질 때만 생성되는 델타 패치
- `UnHelper_Setup.exe`: `--installer` 빌드 시 생성되는 초기 설치본

앱 설정의 Beta 채널을 켜면 GitHub prerelease도 업데이트 대상으로 포함하고, 끄면 최신 정식 릴리즈 복구를 지원합니다. 최초 릴리즈에는 비교할 이전 매니페스트가 없으므로 델타 패치가 생기지 않는 것이 정상입니다.
